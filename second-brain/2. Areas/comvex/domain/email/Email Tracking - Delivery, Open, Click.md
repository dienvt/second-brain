# Email Tracking — Delivery, Open, Click

How Digima tracks the lifecycle of a sent email (delivered / bounced / opened / clicked), and how those signals flow back into [[Workflow]].

## TL;DR

| Signal                                                                            | How captured                                                                              | Stored in                         | Event fired                 | Workflow trigger?                          |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------- | --------------------------- | ------------------------------------------ |
| **Delivered / bounced / dropped / spam / deferred / processed / queued / failed** | SendGrid Event Webhook → `ParseRawSendgridEventsJob` → `StoreSendgridEventsForAccountJob` | `email_envelope_recipient_events` | `SendgridEventsStoredEvent` | ❌ No                                       |
| **Opened**                                                                        | Tracking pixel `GET /email/v2/open` → `CreateOpenJob`                                     | `email_envelope_opens`            | `OpenedEvent`               | ❌ No await event for opens                 |
| **Clicked**                                                                       | Redirect `GET /email/v2/click` → `CreateClickJob` (also creates an implicit open)         | `email_envelope_clicks`           | `ClickedEvent`              | ✅ `Action::AWAIT_EVENT_EMAIL_LINK_CLICKED` |

> Workflow-sent emails go through the same `Envelope` machinery, so all three pipelines apply unchanged. The **only** workflow-actionable email signal is **link clicked**.

---

## 1. The unit of tracking: `Envelope`

All tracking attaches to an `Envelope`. **Envelope-to-recipient cardinality depends on email type:**

| Email type | Envelope ↔ Recipient | Notes |
|---|---|---|
| **Bulk email** (manual blast) | 1 envelope = 1 recipient | Each recipient gets their own envelope row |
| **Workflow email** (`Action::TYPE_SEND_EMAIL`) | 1 envelope = 1 recipient | `EnvelopeCreator->createEnvelope(collect([$participant->contact]))` — always single contact |
| **Classic email** | 1 envelope = many recipients | 1 `to` (the **main recipient**, the one Digima considers tracked) + many `cc` / `bcc` |

> Source: thread with Anderson Oki, 2026-05-15. Classic emails ship as a **single email with one shared `message_id`** so reply-all preserves the thread; you cannot split into N envelopes without breaking the thread.

```
Email
 └─< Envelope
       ├─< Recipient (1 for bulk/workflow, N for classic — 1 `to` + many `cc`/`bcc`)
       │     └─< Recipient\Event   ← SendGrid lifecycle, PER RECIPIENT (delivered, bounced, …)
       ├─< Open                    ← pixel beacon, PER ENVELOPE (see §3.1)
       ├─< Click                   ← link redirect, PER ENVELOPE (see §4.1)
       ├─< Unsubscribe
       └─  Statistic (denormalised counters)
```

### Why opens/clicks are per-envelope but delivery events are per-recipient

The email **body is identical for all recipients** of a single envelope — for classic email, all `to`/`cc`/`bcc` receive the same rendered MIME with the same embedded pixel URL and the same rewritten click links. The tracking code (`?openCode=abc`, `?clickCode=xyz`) is baked into the body and **cannot be parameterised per recipient** without sending separate emails (which would lose the thread for reply-all).

→ When someone opens/clicks, we know **the envelope was opened/clicked** but not **which recipient** did it.

SendGrid's webhook, on the other hand, fires per recipient address (it tracks SMTP delivery per address) — so `email_envelope_recipient_events` *is* per recipient.

For bulk/workflow emails this distinction is moot since envelope ↔ recipient is 1:1 anyway.

Models — all in `app/Models/Account/Email/Envelope/`:

- `Envelope.php` — the sent email
- `Recipient/Recipient.php` — resolved recipient
- `Recipient/Event.php` — delivery lifecycle events (one row per SendGrid event)
- `Open.php` — open records (pixel-driven)
- `Click.php` — click records (redirect-driven)
- `Statistic.php` — aggregate counters (denormalised, used by UI)

Tables live in the **per-account MySQL DB** (`dgm_account_{id}`).

## 2. Delivery status (delivered / bounced / dropped / spam …)

**Source:** SendGrid Event Webhook. **Not** generated by our app.

### Pipeline

1. SendGrid `POST /sendgrid/v2/events` — `routes/sendgrid/v2/sendgrid.php:6`
2. `Sendgrid\v2\EventsController::store` chunks payload (100 events/chunk) and dispatches `ParseRawSendgridEventsJob` — `app/Http/Controllers/Sendgrid/v2/EventsController.php:23`
3. `ParseRawSendgridEventsJob` validates required keys (`account_id`, `envelope_id`, `email_id`, `sg_event_id`, `timestamp`, `event`, `email`), groups by `account_id` + `sg_event_id`, then dispatches one `StoreSendgridEventsForAccountJob` per account
4. `StoreSendgridEventsForAccountJob`:
   - `DatabaseManager::connectToAccountDatabase($accountId)` — switches to the per-account DB
   - Maps SendGrid event → Digima event via `Event::convertSendgridEventName`
   - **Dedupes by `provider_id`** (= `sg_event_id`) — prevents double-write on SendGrid retries
   - Bulk inserts into `email_envelope_recipient_events` with raw payload preserved in `provider_payload`
   - For bounce/spam/dropped → dispatches `RegisterExclusionJob` (auto-add to exclusion list)
   - Fires `SendgridEventsStoredEvent($envelopeId, $countsByEventName)` per envelope
5. `Listeners/Email/Envelope/UpdateStatisticSubscriber::whenSendgridEventsStored` — increments aggregate `Statistic`

### Event constants — `Recipient\Event.php:42-57`

```php
NAME_BOUNCED    = 'bounced'
NAME_DEFERRED   = 'deferred'
NAME_DELIVERED  = 'delivered'
NAME_DISPATCHED = 'dispatched'
NAME_DROPPED    = 'dropped'
NAME_FAILED     = 'failed'
NAME_PROCESSED  = 'processed'
NAME_QUEUED     = 'queued'
NAME_SPAM       = 'spam'
```

Bounce sub-type stored in `meta.type`: `hard_bounce` / `soft_bounce` / `unidentified_bounce`.

## 3. Open tracking — pixel beacon

### Mechanics

- Email body embeds `<img src=".../email/v2/open?...openCode=...">` — pixel image content from `config('mail.tracking.pixel_src')`.
- Route: `routes/email/v2/guest.php:9` → `Email\v2\OpensController@store`
- Throttle: **`throttle.email_opens:1,3600`** — 1 hit per hour per opener (prevents over-counting from preview panes / re-renders)
- v3 equivalent: `app/Http/Controllers/Email/v3/OpensController.php`

### Pipeline — `OpensController::store`

1. Decode `openCode` (base64) → `OpenAttributeExtractor::extractAttributes` → `{account_code, envelope_code | (email_id, contact_id), ip_address?, user_agent?}`
2. Resolve `Account::findByCode`, check `isEnabled()`
3. `DatabaseManager::connectToAccountDatabase($account->id)`
4. Dispatch `CreateOpenJob`
5. **Always** return the 1×1 GIF (200 OK) regardless of success — the response is the pixel

### `CreateOpenJob` — `app/Jobs/Email/Envelope/Open/CreateOpenJob.php`

- Resolves envelope by `envelope_code` or by `(email_id, contact_id)`
- **Dedupe rule** (line 64-75): if an `Open` already exists with the **same `opened_at` AND same `user_agent`**, skip
  > Some clients fetch the pixel twice; this catches that.
- Inserts `{envelope_id, opened_at, ip_address, user_agent}`
- Fires `Email\Envelope\OpenedEvent($open)`
- Sender notification — `EmailOpenedNotification`:
  - First open → `Email::NOTIFY_OPENS`
  - Subsequent → `Email::NOTIFY_REOPENS` (`Open::fetchByEnvelope($envelope)->isNotEmpty()`)

## 4. Click tracking — link redirect

### Mechanics

- Outbound `<a href>` URLs are rewritten to `.../email/v2/click?clickCode=...`
- Route: `routes/email/v2/guest.php:6` → `Email\v2\ClicksController@store`
- Throttle: `throttle.any:20,60` — 20/min
- v3 equivalent: `app/Http/Controllers/Email/v3/ClicksController.php`

### `CreateClickJob` — `app/Jobs/Email/Envelope/Click/CreateClickJob.php`

1. Resolve envelope (by `envelope_code` or `(email_id, contact_id)`)
2. Resolve `Link` (by `link_code` or `link_id`)
3. **Implicit open** (line 70-73, 131-141): if email tracks opens **and** envelope has zero opens yet → dispatch `CreateOpenJob` first
   > A click counts as an open even if the pixel never fired.
4. Insert `{envelope_id, link_id, clicked_at, ip_address, user_agent}`
5. Fire `Email\Envelope\ClickedEvent($click)`
6. Notify sender (`EmailLinkClickedNotification`) when `Email::NOTIFY_CLICKS` is on

## 5. Workflow-sent emails

Workflow `Action::TYPE_SEND_EMAIL` executes through `app/Services/Workflow/Action/EmailActionExecutor.php`:

```php
$envelopeCreator = new EnvelopeCreator($email);
$envelopeCreator->createEnvelope(collect([$this->participant->contact]));
```

Always **1 envelope = 1 recipient (the participant's contact)** — so opens/clicks can be unambiguously attributed to that one contact. Same envelope creation as a normal send → **all three tracking pipelines (delivery/open/click) work identically**.

## 6. Workflow reactions to email signals

`app/Listeners/Workflow/MatchSubscriber.php` subscribes to:

| Event | Listener | Workflow await event fired |
|---|---|---|
| `EnvelopeOpenedEvent` | `whenEnvelopeOpened` (line 335) | **none** — no `AWAIT_EVENT_EMAIL_OPENED` constant exists |
| `EnvelopeClickedEvent` | `whenEnvelopeClicked` (line 278) | `Action::AWAIT_EVENT_EMAIL_LINK_CLICKED` |
| `InboxEnvelopeLinkClickedEvent` | `whenInboxEnvelopeLinkClicked` (line 295) | `Action::AWAIT_EVENT_EMAIL_LINK_CLICKED` |
| `SmsMessageClickedEvent` | `whenSmsMessageClicked` (line 321) | (SMS) |
| `SendgridEventsStoredEvent` | — | not consumed by workflow |

> ⚠️ **Opens do not advance workflows.** They update statistics only. Delivery/bounce status also does not drive workflow.

The only workflow-actionable email signal is **link clicked**.

## 9. End-to-end sequence (workflow email click)

```
1. Workflow scheduler / executor
   → SendEmailActionExecutor → EnvelopeCreator
   → email-api sends via SendGrid
   → Envelope row + Recipient rows created in dgm_account_{id}

2. SendGrid delivers → POST /sendgrid/v2/events {event: "delivered", ...}
   → ParseRawSendgridEventsJob
   → StoreSendgridEventsForAccountJob
   → Recipient\Event row (name=delivered)
   → SendgridEventsStoredEvent → Statistic++

3. User opens email → GET /email/v2/open?openCode=...
   → CreateOpenJob
   → Open row
   → OpenedEvent → Statistic++ ; sender gets EmailOpenedNotification

4. User clicks link → GET /email/v2/click?clickCode=...
   → CreateClickJob
       → (if no Open yet) dispatch CreateOpenJob first   [implicit open]
   → Click row
   → ClickedEvent
       → UpdateStatisticSubscriber → Statistic++
       → MatchSubscriber::whenEnvelopeClicked
           → ContactMatchedEvent($contactId, AWAIT_EVENT_EMAIL_LINK_CLICKED)
           → workflow participant advances past its `await_event` step
   → user redirected to original URL
```
